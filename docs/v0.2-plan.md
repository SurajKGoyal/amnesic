# amnesic v0.2 — Knowledge Lifecycle Management (tracked plan)

**Theme:** When developers rotate projects, annotations shouldn't die with their
access. v0.2 makes knowledge portable, handles schema drift, and lets you retire
stale annotations without losing history.

> An item is only marked ✅ **after the code is read and the criteria are
> verified** — never on assumption. A grep match is not verification; the
> behaviour must be confirmed (a test, a run, or reading the implementation
> end-to-end).

## v0.2.0 — Deprecation + Drift (the headline slice)

### 0. Store migration — `deprecated_*` columns  *(foundation, blocks #1/#2)*
Add `deprecated_at TEXT` and `deprecated_reason TEXT` to `table_knowledge` and
`column_knowledge`.
- **Acceptance:** opening a pre-v0.2 `.db` file adds the columns automatically;
  no data loss; idempotent (second open is a no-op).
- **Verification:** unit test — create a store with the old schema, open it with
  the new code, assert both columns exist and existing rows are intact.
- **Files:** `store.py`
- **Status:** ✅

### 1. `db_deprecate(table, connection, column=None, reason="", undo=False)`  *(#1)*
Soft-delete: set/clear `deprecated_at` + `deprecated_reason`. Reversible.
- **Acceptance:**
  - Deprecating a table sets its flag; `column=...` deprecates a column.
  - `db_get_schema` and `db_search` responses include `deprecated: true` +
    `deprecated_reason` for flagged items.
  - `undo=True` clears the flags.
  - Deprecated items remain stored and searchable (soft, not hard delete).
- **Verification:** unit test the store methods + a test asserting the flag
  surfaces in `db_get_schema` / `db_search` output.
- **Files:** `store.py`, `tools/schema.py`, `tools/search.py`, `tools/knowledge.py`,
  `server.py`
- **Status:** ✅

### 2. `db_detect_drift(connection)`  *(#2)*
Compare stored annotations against the live schema.
- **Acceptance:** returns `{orphaned_annotations: [...], undocumented_tables: [...]}`
  where orphaned = annotated table/column no longer in live schema; undocumented =
  live table with no annotation. Read-only (no writes to the DB).
- **Verification:** unit test against a fixture schema with a deliberately
  orphaned annotation and an unannotated table; assert both are caught.
- **New work:** per-driver "list all live tables/columns" introspection (today
  schema is fetched one table at a time).
- **Files:** `store.py`, `tools/schema.py` (introspection SQL), new
  `tools/drift.py`, `server.py`
- **Status:** ✅

### 3. `db_forget(table, connection, column=None)`  *(#8 — completes the loop)*
Hard-delete a single table or column annotation. The remediation action that
`db_detect_drift` calls for: when an annotation points at a column that no longer
exists (orphaned), or was simply wrong, remove it cleanly — not just flag it.
- **Decision (locked): cascade is opt-in — safe by default.** The destructive
  table-wide nuke can't happen by accident; you must pass `cascade=True`.
  Signature: `db_forget(table, connection, column=None, cascade=False)`.
- **Acceptance:**
  - `db_forget(table)` → delete ONLY the `table_knowledge` row (description +
    aliases). Column annotations and relationships are left untouched.
  - `db_forget(table, column="x")` → delete ONLY that column's `column_knowledge`
    row.
  - `db_forget(table, cascade=True)` → the deliberate nuke: delete the
    `table_knowledge` row + all `column_knowledge` rows for that table + all
    `table_relationships` rows where the table is either endpoint.
  - **Every** call returns a count of what was removed:
    `{removed_table: bool, removed_columns: n, removed_relationships: n}` — blast
    radius always visible.
  - Permanent (unlike `db_deprecate`, which is reversible).
  - FTS index stays consistent (delete triggers fire on row removal).
  - Does **not** touch the live database — only the local knowledge store.
- Context-based deletion of a specific wrong annotation is handled by the
  LLM-as-caller: the AI picks the target from conversation and calls the
  narrowest form. Single-relationship-edge deletion is out of scope for 0.2.0.
- **Verification:** unit test — annotate a table + columns + a relationship,
  `db_forget` it, assert the rows AND the FTS entries are gone and siblings remain.
- **Files:** `store.py`, `tools/knowledge.py`, `server.py`
- **Status:** ✅

**Lifecycle now complete:** `db_detect_drift` (find) → `db_deprecate` (soft-retire)
→ `db_forget` (hard-delete).

**Ship 0.2.0:** bump 4 version fields → `git tag v0.2.0 && git push` → auto-pipeline.

## v0.2.1 — Portable knowledge (team handoff)

### 3. `amnesic export` / `import` CLI  *(#3)*
- `export <conn> [--output f.json]` — dump annotations + relationships (NOT
  `schema_cache`, which is re-derivable) with `{format_version, exported_at,
  source}` metadata.
- `import <conn> <file.json>` — unconditional upsert of annotations +
  relationships (handoff = load everything, unlike `db_sync_knowledge`).
- **Acceptance:** `export` then `import` into a fresh connection reproduces the
  same annotations + relationships (round-trip equality). Unknown
  `format_version` is rejected with a clear error.
- **Verification:** round-trip unit test (export → wipe → import → assert equal).
- **Files:** `cli.py`, `store.py` (bulk read/write helpers)
- **Status:** ✅ — shipped in **v0.2.2** (slipped past the 0.2.1 release, which was
  the credential-scrubbing slice). `store.export_knowledge/import_knowledge`,
  `amnesic export/import` CLI, `format_version` guard. Round-trip test in
  `tests/test_cli_lifecycle.py::TestExportImport` (deprecation flags survive).

## v0.2.2 — Connection cleanup + DX

### 4. `amnesic remove` / `clear` CLI  *(#4)*
- `remove <conn>` — drop from `connections.toml` (structure-preserving),
  optionally delete the knowledge file (`--delete-knowledge` or prompt).
- `clear <conn>` — wipe knowledge rows, keep the config entry.
- **Acceptance:** `remove` deletes only the target connection's TOML block, leaves
  others intact; `clear` empties knowledge but the connection still lists.
- **Verification:** unit test on a multi-connection TOML — assert only the target
  block is gone and siblings are byte-for-byte preserved.
- **Files:** `cli.py`, `store.py`, `config.py`/`_paths.py`
- **Status:** ✅ — `amnesic remove` (string-surgical TOML block delete, optional
  `--delete-knowledge`) + `amnesic clear` (wipe rows, keep config). Added
  `store.clear_knowledge`, `close_store`, and `config.list_connection_names`
  (name-only lookup so a broken sibling connection can't block local commands).
  Tests in `tests/test_cli_lifecycle.py::TestRemoveConnectionBlock` /
  `::TestRemoveClear`.

### 5. Version-update notice  *(#7)*
On CLI commands only (never MCP-server mode): check PyPI latest vs installed.
- **Acceptance:** prints a one-line notice when newer exists; **cached 24h** in a
  state file (no PyPI call on every invocation); opt-out via env var; fail-silent
  on any network/parse error; **never** runs in server mode.
- **Verification:** unit test — mock PyPI response, assert notice logic; assert
  cache prevents a second network call within 24h; assert server mode skips it.
- **Files:** `cli.py`, new `_update_check.py`
- **Status:** ✅ — `_update_check.py` (24h file cache, `AMNESIC_NO_UPDATE_CHECK`
  opt-out, fail-silent, injectable `now`). Wired into the CLI group via
  `_maybe_print_update_notice` → stderr, gated so it never runs in MCP-server
  mode (no-subcommand + piped stdin) or under pytest. Tests in
  `tests/test_update_check.py` (fresh-cache-skips-network, stale-refetch,
  opt-out, fail-silent).

### 5b. `amnesic init` writes `.env.example` (closes #5)
- **Acceptance:** see #5 remaining criteria above.
- **Files:** `cli.py` / `_wizard.py`
- **Status:** ✅ — `_write_env_example()` writes a commented `.env.example`

## Execution notes

- **Not parallelizable.** #0/#1/#2 share `store.py`; #3/#4/#5b share `cli.py`.
  Per the "shared files ⇒ not independent" rule, build sequentially (or in the
  three slices above), not via parallel worktrees.
- **Every store change is backwards-compatible** — old `.db` files auto-upgrade
  on first open (same pattern as the v0.1.5 FTS backfill).
- **Release per slice** via the unified pipeline: bump `pyproject.toml`,
  `amnesic/__init__.py`, and both `server.json` version fields to the same value,
  then tag. The pipeline's guard fails the release if they ever disagree.
